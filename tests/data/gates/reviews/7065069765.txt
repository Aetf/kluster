**S1. The chart-side coverage case misses a second gap, besides the one the design names.** `tests/test_operator_updates.py:412`

`rendering` is the set of keys whose record has `<key>.spec.managedMetadata.annotations`. `update_crds` writes that path only for the maps listed in `SPEC_PASS_THROUGH` (`src/kluster/scripts/update_crds/values.py:76-85`), a hand-written list that equals `CHART_RESOURCES`. So the check is only as complete as a second hand list.

Failure scenario, reproduced: I added `'vmauth': {'enabled': True}` to `_stack_values`, and both coverage cases stayed **green**. `VMAuth` has `spec.managedMetadata` in the bundle and renders a Deployment, so the chart would install a VM resource with no mark. The same holds for `vmcluster`, `vlsingle`, `vlagent`, `vtsingle` and the others.

The PR's live check (§7 item 1) runs once, on this merge, so a later PR that turns one of these on has no backstop. The test's docstring ("names `<key>.spec.managedMetadata.annotations` for every key the chart renders such a resource from") is false for those keys.

The rewrite I would accept is by definition, from the record alone. A top-level key whose record has `<key>.spec` is a resource the chart renders from that key's spec. Today exactly the operator keys have that path: `alertmanager`, `vlagent`, `vlcluster`, `vldistributed`, `vlsingle`, `vmagent`, `vmalert`, `vmauth`, `vmcluster`, `vmdistributed`, `vmsingle`, `vtcluster`, `vtsingle`.

```python
resources = {key for key in tops if f'{key}.spec' in paths}           # what the chart renders a spec from
assert resources & configured <= marked                               # every configured one is marked
assert marked <= {key for key in resources if f'{key}.spec.managedMetadata.annotations' in paths}
```

With this, enabling `vmauth` turns the case red. Marking it then forces a `SPEC_PASS_THROUGH` entry, so the record carries its `managedMetadata` path. If a kind without `managedMetadata` is ever turned on, the case asks for a decision, which is the safe direction. The other acceptable fix is to name this residual next to the design's one: in the module docstring, the test docstring and the PR body.
